- Current parallel processing has element-category fallback to sequential
- WASM uses `wee_alloc` with minimal/enhanced dual-path strategy

**Critical Files**:
- `crates/core/src/ast.rs` - Document/Element/Node definitions
- `crates/core/src/optimizer/mod.rs` - Multipass pipeline orchestration
- `crates/core/src/parser/main.rs` - Quick-xml streaming parser

## Recommended Execution Strategy

### Approach: Sequential Waves with Maximum Parallelization
**Execute Wave 1 → Wave 2 → Wave 3**, with parallel execution of independent tasks within each wave.

**Rationale**:
- Wave 1 establishes architectural foundations (arena allocation, CSS integration, memory budgeting)
- Wave 2 builds intelligence features that depend on Wave 1 infrastructure
- Wave 3 focuses on distribution and ecosystem, depending on stable core
- This approach balances speed (parallelization) with safety (dependency management)

### Testing Rigor: Standard Verification
**Per-task**: Build + test + clippy + format  
**Per-wave**: Integration tests, benchmark stability check, documentation update  
**Final**: Cross-platform CI verification (macOS, Linux, Windows)

**Rationale**:
- Balances thoroughness with execution speed
- Catches regressions early without over-testing
- CI handles platform-specific validation

### Skill Assignment Notes
Custom skill names (e.g., `Rust-Memory`, `Rust-SIMD`) are **domain descriptors** for Coder agent context. They inform which expertise areas the task requires but don't need to map 1:1 to predefined skills. The `category` field (ultrabrain/deep/etc.) is the primary execution strategy selector.
